# HANDOVER-А (пример заполнения)

Вымышленный проект: сервис счетов `invoice-service`. Файл показывает, как выглядит заполненная передача состояния.

## Зона

- Владеет: `app/core/`, `app/core/public.py`, миграции `alembic/versions/core_*`
- Чужие зоны: `app/billing/` (сессия Б), `app/notify/` (сессия В)
- Суффикс тестовой БД: `_a`
- Команда тестов зоны: `pytest -q tests/core tests/test_boundaries.py`

## Состояние

- 2026-10-05: добавила `core.public.get_invoice(id)`, чтобы Б не лезла в таблицы ядра напрямую. Коммит `3fa91c2`. Проверено на стенде: запрос по существующему и несуществующему счёту, второй возвращает `None`, не исключение.
- 2026-10-03: миграция `core_0012` (ADD COLUMN `paid_at`), отметки по старым счетам проставлены задним числом, иначе первый запуск разослал бы напоминания по всей истории. Коммит `b71e0d4`.

## Решения и границы

- Модуль `billing` обращается к ядру только через `core.public`. Причина: прямые импорты уже раз ломали сборку при переименовании таблицы.
- Миграции только аддитивные. Причина: откат деплоя по хешу не должен требовать отката схемы.
